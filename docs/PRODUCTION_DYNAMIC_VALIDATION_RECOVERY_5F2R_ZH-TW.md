# 5-F.2-R｜正式更新動態驗證復原

## 失敗原因

第一次華山正式更新已成功完成來源擷取、合併、品質閘門與
Finalizer，並將正式候選寫入暫存工作目錄。

失敗發生在後續重新執行全部單元測試時。部分舊測試將
`2,424` 筆活動與特定活動內容視為固定測試資料；正式更新後
活動變成 `2,474` 筆，因此測試失敗。

這不是正式資料品質錯誤，也不是華山 Collector 失敗。

## 修正架構

1. 在任何正式資料變動前執行完整 255+ 項專案測試。
2. 正式資料產生後，不再用固定資料快照測試重新檢查。
3. 改用動態正式資料驗證器，檢查：
   - 最低活動數
   - 活動 ID 完整且唯一
   - 標題與日期格式
   - 無 `exclude_review`
   - 無舊分類名稱
   - stats 與活動資料一致
   - 官方來源參照唯一
   - 正式發布標記與來源一致
4. Workflow 修正合併到 main 時，自動以
   `production-pipeline-recovery` 模式重新執行正式更新。
5. 將幾個依賴固定活動數或特定活動仍存在的測試改為動態不變量。
6. 在每次重建 enriched 基底時重新套用分類名稱正規化：
   `歷史文化 → 歷史`、`自然科學 → 自然`、`快閃 → 快閃店`，並保持演唱會為獨立分類。

## 安全性

- 不降低正式資料安全門檻
- 不跳過來源完整詳情頁驗證
- 不跳過去重、人工審核與 Finalizer
- 失敗時仍不 Commit、不部署
- 正式資料驗證通過後才 Commit 與部署
