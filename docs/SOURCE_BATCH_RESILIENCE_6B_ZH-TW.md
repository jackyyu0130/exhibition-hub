# 6-B｜來源失敗隔離、重試與健康報告

## 目的

6-A 已建立通用批次執行器。6-B 強化執行安全，
避免單一場館暫時失敗時拖垮整批來源。

## 執行策略

- 每個來源使用獨立 Python 子程序
- 每個來源有獨立 timeout
- 失敗後依設定重試
- 重試採倍增等待時間
- 單一來源最終失敗時，其他來源繼續執行
- 每次嘗試都保留狀態、耗時與錯誤
- 成功重試標記為 recovered
- timeout 與慢速來源獨立統計

## 預設值

- 每個來源最多 3 次嘗試
- 重試基礎等待 2 秒
- 單一來源 timeout 180 秒
- 90 秒以上標記為慢速來源

批次可以在 `data/source_batches.json` 個別覆蓋預設值。

## 健康狀態

- `healthy`：全部首次成功，無警告與慢速來源
- `degraded`：有重試恢復、timeout、警告、慢速或局部失敗
- `unhealthy`：整批沒有可用成功來源
- `skipped`：批次沒有實際執行來源

## Dry Run

仍使用既有：

`.github/probe-source-batch.trigger`

一次 Dry Run 會同時執行：

1. 真實華山批次與完整詳情頁
2. 真實健康報告驗證
3. 可重現的重試／timeout／來源隔離模擬

## 本階段不會做的事

- 不新增新場館來源
- 不修改正式活動資料
- 不修改前台
- 不接入正式每日發布
- 不變更華山正式更新頻率
